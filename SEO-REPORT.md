# SEO report — gogameskhi.com

Prepared 22 November 2026 for the official website of Goga Meskhi (გოგა მესხი), hosted on GitHub Pages behind Cloudflare DNS at `https://gogameskhi.com`.

For bilingual keyword ownership, page-level primary/secondary terms, and priority-phrase coverage, see **`SEO-KEYWORDS.md`** (regenerated by `python seo_keyword_audit.py` after `python build.py`).

**Status: implemented and verified locally; not yet committed or deployed.** The live site still serves the previous version, which carries `noindex, nofollow` on every page and has no `robots.txt` or `sitemap.xml`. Publishing is a `git push` to `main` (section 7). Read section 6 first: three of the open issues are decisions for the artist, because publishing makes the site visible in search for the first time.

## 2. Audit findings (before the changes)

The whole codebase was reviewed: the generator `build.py`, the 47 generated pages, `assets/style.css`, `assets/main.js`, `make_preview.py`, the content notes and the hosting files.

1. **Every page was blocked from search** with `<meta name="robots" content="noindex, nofollow">`.
2. **No canonical links**, and the English homepage existed at two URLs (`/` and `/en/index.html`) with identical content.
3. **hreflang used relative URLs** (`../ka/about.html`), which search engines ignore, and there was no `x-default`.
4. **Titles were generic** (`About | Goga Meskhi`), and one description was reused on 14 pages in each language. The track page and the story page for "I Don't Remember" had the same title.
5. **Open Graph was incomplete**: no `og:url`, `og:image`, `og:locale` or `og:site_name`, and no X card tags.
6. **Structured data was a single `Person`** without an identifier, URL or link to the pages, and the list of profiles was not the same on every page.
7. **No `robots.txt`, `sitemap.xml` or `404.html`**; no `favicon.ico` or touch icon.
8. **Heading levels skipped** from `h1` to `h3` on eight pages (music, videos, stories and listen, in both languages).
9. **All 86 video thumbnails shared one generic alt text** per language ("Music video thumbnail", "ვიდეოს მინიატურა"), no image had `width`/`height`, and only 18 of the 91 images loaded lazily.
10. **Internal links to the homepages pointed at `en/index.html` and `ka/index.html`** rather than the canonical `/` and `/ka/` (147 links).
11. **Georgian-script text on English pages had no `lang` attribute**, so screen readers would read it with English pronunciation rules.
12. **One press link was broken**: the 2016 Radio Fortuna article returned 404 because of a typo in the address (`math-soris` instead of `math-shoris`).
13. `build.py` crashed on Windows because of a path separator, so the site could not be regenerated on this machine.

## 3. What was implemented

All metadata is produced by `build.py`, so the two languages cannot drift apart. No framework or dependency was added; the generator and the audit script use only the Python standard library.

### URLs, languages, canonical and hreflang

| Page | English | Georgian | `x-default` |
|---|---|---|---|
| Homepage | `https://gogameskhi.com/` | `https://gogameskhi.com/ka/` | `https://gogameskhi.com/` |
| Inner pages | `https://gogameskhi.com/en/<page>.html` | `https://gogameskhi.com/ka/<page>.html` | the English page |

- Each page has `<html lang="en">` or `<html lang="ka">`, a self-referencing canonical link, and `ka`, `en` and `x-default` alternates that point at each other.
- `en/index.html` is kept so that old links still work, but its canonical link points to `/`, it carries no hreflang, and it is not in the sitemap.
- Homepage links are written as folders (`./`, `../`, `ka/`) so that internal links match the canonical URLs. A small addition to `main.js` appends `index.html` to those links only when the site is opened from disk (`file://`), so the local preview described in the README still works.
- The language switcher links carry `hreflang`, and Georgian-script titles on English pages are marked `lang="ka"`.

### Titles and descriptions

Each of the 46 canonical pages has its own title and description in its own language. Section pages use hand-written text held in `PAGE_META` in `build.py`. Track pages use the track title in both scripts ("Melikishvili Avenue (მელიქიშვილის გამზირი) — Goga Meskhi") and the existing track description. Story pages combine the story title, the track name and existing story text. No new facts were written; every description is drawn from content already on the page.

### Open Graph and X cards

Every page has `og:site_name`, `og:type`, `og:title`, `og:description`, `og:url`, `og:locale` (`en_US` or `ka_GE`) with its alternate, and `og:image` with type, width, height and alt text, plus `summary_large_image` X card tags. All URLs are absolute.

- `og:type` is `music.song` on track pages (with `music:musician`), `article` on story pages, `profile` on the About page and `website` elsewhere.
- Track and story pages use the artist's own YouTube thumbnail for that recording.
- All other pages use `assets/goga-meskhi-share-card.png`, a 1200×630 card made from the site's own typography and colours. **It contains no photograph**, because the repository holds no licensed photo (see issue 2 in section 6).

### Structured data

Each page carries one JSON-LD graph whose nodes reference each other by `@id`.

| Page | Nodes |
|---|---|
| Every page except `404.html` | `WebSite` (`/#website`), `Person` (`/#person`), a page node, `BreadcrumbList` (not on the homepages) |
| About | `ProfilePage` with the `Person` as `mainEntity` |
| Contact | `ContactPage` |
| Music, Videos, Stories, Press, Listen | `CollectionPage`; Music, Videos and Stories also carry an `ItemList` |
| Track pages | `MusicRecording` with `byArtist`, and `recordingOf` → `MusicComposition` with composer and lyricist where the page lists them |
| Track pages with a YouTube video | `VideoObject` with name, description, thumbnail, upload date, duration and embed URL |
| Story pages | page node whose `about` is the `MusicRecording` |

The artist is one entity everywhere, `https://gogameskhi.com/#person`:

- `name` "Goga Meskhi", `alternateName` "გოგა მესხი", `givenName`, `familyName`, `jobTitle` Singer and Actor.
- `sameAs` lists only profiles that could be verified: the YouTube channel under both its handle and its permanent channel address, the Facebook page, and the Spotify artist page.
- Not included, because they could not be verified: Instagram (the notes in `RESEARCH-SOURCES.md` mark its status as unconfirmed) and Amazon Music. No birth date, awards, ratings, reviews or event data were added. There is no `image` on the `Person`, because there is no licensed photo.

Video upload dates, durations and thumbnail sizes were read from the eight YouTube watch pages on 22 November 2026; all eight are uploads on the official channel. The audio-only recording "Khval Daitskos" and the duet "Momenatre da Movedi" (which has no YouTube link) have a `MusicRecording` but no `VideoObject`. The album "Love, as it is." is not marked up, because its listing is unconfirmed.

### robots.txt and sitemap.xml

- `sitemap.xml` lists the 44 canonical public pages, each with its `ka`, `en` and `x-default` alternates. It leaves out `en/index.html` (duplicate), `404.html` and the two privacy pages (utility pages; they remain indexable and linked from every footer).
- `robots.txt` allows everything, points to the sitemap, and asks crawlers not to fetch the generator scripts and the `.md` notes that GitHub Pages serves along with the site.
- `404.html` is new: a bilingual page in the site's design with links to both homepages and the music page, marked `noindex, follow`. GitHub Pages serves it automatically for missing addresses.

### Semantics, accessibility and images

- Heading levels no longer skip. The four section pages gained a screen-reader-only `h2` ("Selected recordings", "Music videos", "Song stories", "Channels and platforms") using the site's existing `.sr-only` class. Each is an ordinary section label for assistive technology, not keyword text.
- Every thumbnail's alt text now names its recording ("YouTube thumbnail for "Melikishvili Avenue" by Goga Meskhi"), and the portrait's alt text describes it and credits the source.
- Repeated links ("Listen now", "Details", "Source") have `aria-label`s that say which recording or article they belong to; decorative arrows are hidden from screen readers.
- Press dates are wrapped in `<time datetime>`.
- All 86 thumbnails have `width` and `height` to prevent layout shift. Images below the first screen load lazily; the main image of each page loads with high priority; the homepage hero is preloaded; and there are `preconnect` hints for the thumbnail and font hosts.
- `favicon.ico` and an Apple touch icon were added, both traced from the existing `assets/favicon.svg`.
- Image filenames: the site's own new images have descriptive names. The photos and thumbnails are loaded from other sites, so their filenames cannot be changed.

### Content without JavaScript

All text, navigation and internal links are in the HTML. Video buttons are ordinary links to YouTube that JavaScript upgrades to an in-page player. One limit remains: on narrow screens the header menu opens with a JavaScript toggle. Without JavaScript the same links are reachable in the footer navigation on every page, and crawlers see all of them in the HTML either way.

### Other fixes

- The broken Radio Fortuna link was corrected in `build.py` and in `RESEARCH-SOURCES.md`. The corrected address was found through Fortuna's own search and shows the same article, dated 25 January 2016.
- `build.py` now runs on Windows as well as macOS and Linux, and produces identical output on repeated runs.

## 6. Unresolved issues

### Decisions for the artist before publishing

1. **The portrait photo on the homepage and About page does not load.** It is loaded directly from tbiliselebi.ge, which now answers with a bot check instead of the image, in a normal browser as well as for crawlers. Visitors see the dark placeholder. This was already the case before this work. It cannot be fixed without an image file the artist has the right to use; copying the photo into the repository would be publishing it without permission.
2. **No licensed photograph exists in the project.** `PHOTO-CREDITS.md` states that the listed sources are "not a claim of licensed use". The hero photo is loaded from Radio Fortuna's server and can disappear at any time. For this reason link previews use a typographic card and the `Person` data has no image. Once a licensed photo is supplied, save it in `assets/` under a descriptive name (for example `goga-meskhi-portrait.jpg`), point `assets/photo-sources.json` at it, and set it as `SHARE` in `build.py`.
3. **Wording that describes the site as a draft is now on an indexable site.** The footer of every page reads "Website preview" and "Photo usage rights pending approval" (with the Georgian equivalent on Georgian pages), and the privacy page is headed "How this preview handles information". Earlier notes in the README say `noindex` was kept on purpose until the artist approved the content and photo rights. The tag was removed because indexing is the purpose of this task, but the text was left alone because changing it is an editorial decision. If the approval is still outstanding, do not publish yet.
4. **The Spotify artist page** `open.spotify.com/artist/1CK6M44gPDtqCTHxJq44NI` was identified from the Spotify track already linked on the site. Please confirm it is the artist's own profile; it is listed in `sameAs`. Confirm the Instagram account too if it should be added.

### Content limits that metadata cannot fix

5. **Story pages are short**, and the story for "I Don't Remember" repeats its track page almost word for word. Each has a unique title and description, but search engines may treat them as thin content. They need more original text from the artist.
6. **"I Don't Remember"** is labelled a video on the site, while its YouTube upload is titled "Official Audio". The structured data follows the site. Its date and credits are unverified (see README, V5), so it has no composer or lyricist data.
7. **Three videos have only 640×480 thumbnails** on YouTube (Chamotova Isev, Imgere Rame, Nu Damemdurebi), below the 1200-pixel width Google prefers for large previews.
8. **Video rich results are not guaranteed.** The player loads only after a click, and Google's video features favour pages where the video is the main content and visible on load.

### Technical notes

9. The sitemap has no `lastmod` dates, because the generator has no reliable per-page modification date; invented dates would be worse than none.
10. GitHub Pages also serves `build.py`, `seo_check.py` and the `.md` notes, including this report. `robots.txt` asks crawlers to skip them, but they remain publicly readable. Moving the published site to a `docs/` folder or a separate branch would hide them; that changes the deployment configuration, so it was not done.
11. GitHub Pages answers `/en/about` as well as `/en/about.html`. The canonical link on each page tells search engines which one to index.
12. GitHub Pages cannot send custom HTTP headers or redirects, so `/en/index.html` cannot be redirected to `/`; the canonical link does that job.
13. The mobile menu needs JavaScript (section 3).

## 7. Deployment steps

Nothing has been committed. From `C:\Demo\gogameskhi`:

1. Settle issues 1–4 in section 6, at least issue 3.
2. Rebuild and check:
   ```
   python build.py
   python seo_check.py --external
   ```
   The last line must read `0 errors`.
3. Review and publish:
   ```
   git status
   git add -A
   git commit -m "Add SEO metadata, structured data, sitemap, robots.txt and 404 page"
   git push origin main
   ```
   Confirm that `CNAME` and `.nojekyll` are still in the commit's file list and unchanged.
4. Wait for the build under the repository's **Actions** tab ("pages build and deployment"), usually one to two minutes.
5. Check the live site:
   - `https://gogameskhi.com/robots.txt` and `https://gogameskhi.com/sitemap.xml` open.
   - View source on `https://gogameskhi.com/` and `https://gogameskhi.com/ka/`: the robots tag reads `index, follow`, and the canonical link is the page's own address.
   - `https://gogameskhi.com/anything-missing` shows the new 404 page.
   - Play one video on a track page.
6. In GitHub **Settings → Pages**, keep the custom domain `gogameskhi.com` and "Enforce HTTPS" ticked. In Cloudflare, keep the DNS records as they are (DNS only).
7. Register the site with search engines:
   - Google Search Console: add `gogameskhi.com` as a Domain property (verified with a DNS TXT record in Cloudflare), then submit `https://gogameskhi.com/sitemap.xml` and request indexing of the two homepages.
   - Bing Webmaster Tools: import the site from Search Console and submit the same sitemap.
8. Validate the published pages:
   - Google Rich Results Test (`search.google.com/test/rich-results`) on the homepage, the About page and one track page.
   - Facebook Sharing Debugger and a test post on X for the homepage and one track page, to confirm the preview image and text.
9. Add `https://gogameskhi.com` as the website link on the YouTube channel, Facebook page and Spotify for Artists profile. Links in both directions are what lets search engines connect the profiles to the site.

## 8. Maintenance

- Edit content and metadata in `build.py`, never in the generated HTML. Run `python build.py`, then `python seo_check.py`.
- Section titles and descriptions are in `PAGE_META`; verified profiles in `SAME_AS`; YouTube upload dates and durations in `VIDEO`. A new YouTube video needs an entry in `VIDEO` with data read from its watch page.
- A new page is added to the sitemap and given canonical and hreflang links automatically.
